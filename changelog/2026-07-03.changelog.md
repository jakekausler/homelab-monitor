Also closes a 010A gap where the manual trigger endpoint accepted destructive real-mode calls with no server-side credential check.

### Backend

- New `kernel/security/pin.py` — bcrypt PIN hashing, `InProcessPinRateLimiter` with time-based progressive backoff (3 fails=5s, 4=30s, 5=300s; 15-min sliding window), `verify_destructive_credential` async helper dispatching PIN vs phrase via `PhraseMatchMode.EXACT`/`CASE_FOLD`.
- New `kernel/api/routers/security_pin.py` — `GET /pin` (status), `POST /pin` (set or rotate), `POST /pin/verify`, `DELETE /pin`. All mutations audit `security.pin_*` events. Set/delete require password re-prove with login-rate-limit + audit on wrong password. Rotate requires current PIN with progressive lockout.
- Modified `kernel/api/routers/{autofix,autofix_settings,runbooks}.py` — destructive endpoints accept EITHER `confirm_phrase` OR `confirm_pin` via the shared helper. Trigger endpoint now enforces basename phrase server-side (closes 010A UI-only gap).
