2026-07-03 928a680 EPIC-009 / STAGE-009-010B: Auto-fix UI — session-PIN confirm-on-destructive

### Summary

Replaces the typed-phrase confirm-on-destructive UX with a session-PIN alternative across three auto-fix endpoints (approve, kill-switch, manual trigger). Users can set a numeric PIN in a new Settings → Security page; when set, destructive-action dialogs prompt for PIN instead of the typed phrase. Phrase-fallback preserved when no PIN is configured. Also closes a 010A gap where the manual trigger endpoint accepted destructive real-mode calls with no server-side credential check.

### Backend

- New `kernel/security/pin.py` — bcrypt PIN hashing, `InProcessPinRateLimiter` with time-based progressive backoff (3 fails=5s, 4=30s, 5=300s; 15-min sliding window), `verify_destructive_credential` async helper dispatching PIN vs phrase via `PhraseMatchMode.EXACT`/`CASE_FOLD`.
- New `kernel/api/routers/security_pin.py` — `GET /pin` (status), `POST /pin` (set or rotate), `POST /pin/verify`, `DELETE /pin`. All mutations audit `security.pin_*` events. Set/delete require password re-prove with login-rate-limit + audit on wrong password. Rotate requires current PIN with progressive lockout.
- Modified `kernel/api/routers/{autofix,autofix_settings,runbooks}.py` — destructive endpoints accept EITHER `confirm_phrase` OR `confirm_pin` via the shared helper. Trigger endpoint now enforces basename phrase server-side (closes 010A UI-only gap). Orchestrator threads `credential_type` through `execute_approved`, `handle_operator_trigger`, `_claim_and_exec`, `_persist_outcome`, `_audit_trigger_rejected`, and `_deny_operator` — every destructive-action audit records which credential type was used.
- Fixed `_handle_http_exception` in `kernel/api/errors.py` to forward `exc.headers` (fixes 429 `Retry-After` propagation through the problem+json envelope).

### Frontend

- New `apps/ui/src/api/security-pin.ts` — TanStack Query hooks: `usePinStatus`, `useSetPin`, `useVerifyPin`, `useDeletePin`. `retryAfterSeconds` extracted from 429 Retry-After header via existing `ApiError`.
- New `apps/ui/src/components/ConfirmPinDialog.tsx` — sibling of `ConfirmPhraseDialog`. Password-masked digit input (`inputMode="numeric"` for mobile keypad). Client-side gate `/^[0-9]{4,12}$/`. Live countdown with unified "Too many wrong attempts. Please wait Ns before trying again." message during lockout; ref-guarded transition detection + interval-clear-at-0 + `showError` suppression to avoid stale error flash.
- New `apps/ui/src/routes/settings/SettingsSecurityPage.tsx` at `/settings/security` — set/rotate/delete flows with matching countdown UX. Same ref-guarded pattern applied to the bespoke Rotate dialog inline state.
- Modified `ApprovalPlanDialog.tsx`, `SettingsAutofixPage.tsx` (kill-switch), `RunFixDialog.tsx` — conditional dialog: `usePinStatus().set === true` mounts `ConfirmPinDialog`, else `ConfirmPhraseDialog`. Mutation body widened to include `confirm_pin?: string`. Trigger phrase-fallback now sends `confirm_phrase: runbookName` in body (matches new server-side gate). RunFixDialog no longer closes on 429 — countdown remains visible.

### Refinement-caught bugs (fixed here, not deferred)

- **Backend rate-limiter time-based lockout**: original `check()` returned "still locked" for the full 15-min sliding window instead of just the tier's lockout_seconds. Fixed to compare elapsed time since last failure against the tier duration; ceiling-rounded remaining seconds. Regression tests added.
- **UI countdown bugs**: interval never cleared at 0 (cleared input every second); errorMessage re-flashed when countdown expired. Fixed with `wasLockedRef` + interval-clear-at-c<=1 + local `showError` state.

### Finalize (code-review-driven changes)

- Rate-limit + audit on `set_pin` / `delete_pin` wrong-password paths (mirrors change-password precedent). Prevents password brute-force via PIN endpoints.
- `_client_ip()` in security_pin.py no longer honors `X-Forwarded-For` (audit-IP spoofing hardening).
- `credential_type` threaded through operator-denied audits in orchestrator (`_deny_operator`, in-lock claim denial).
- Router param annotations tightened from `Annotated[object, ...]` to real types (AuthRepository, AppSettingsRepository, InProcessPinRateLimiter, LoginRateLimiter).
- Shared `PIN_REGEX_STR` constant + `.casefold()` in CASE_FOLD phrase branch + `math.ceil` in lockout remaining computation.

- New `POST /api/runbooks/{runbook_id}/trigger` endpoint: operator-initiated manual trigger with body `{mode: 'dry_run' | 'real'}`.
