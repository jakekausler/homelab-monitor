# STAGE-009-007: Kill switch — pre-run gate + mid-run kill + dashboard control

## Status: Complete

## Overview

Implement the global kill switch (non-negotiable #7): a single boolean in the existing `app_settings` table (`autofix_enabled`) that the orchestrator checks before EVERY run, plus the ability to terminate a run **mid-flight** via `docker kill` of the `fixer-runner` container. Expose a single dashboard control (with confirm-on-destructive) that toggles it, audited. When the switch is off, all auto-fix is disabled immediately; an in-flight run is killable.

**Vertical slice:** after this stage, toggling the kill switch off denies all new runs (within ~100ms) and kills any in-flight run; the dashboard control toggles it with a confirm step and writes an audit row. This layers onto the STAGE-009-005 orchestrator.

**Spec references:** §7.4 (#7 kill switch — single dashboard control, killable mid-run via `docker kill` or POSIX signal), §7.2 (confirm-on-destructive on the kill-switch toggle), §6.1 (`app_settings` key-value store from STAGE-004-022; `audit_log`). EPIC-009 LOCKED Decision 1 (container → `docker kill`).

## Concrete deliverables

### 1. Kill-switch storage + pre-run gate

`app_settings` key `autofix_enabled` (boolean). The orchestrator reads it before every run; off → deny + record reason. Fast path (<100ms).

### 2. Mid-run kill

Terminate an in-flight run via `docker kill` of the `fixer-runner` container (or signal). The partial run is recorded (audit + `runbook_runs` with the kill reason + exit state).

### 3. Dashboard control

A single toggle in the UI (Settings or the Runbooks/Auto-fix screen) with confirm-on-destructive. Audited on toggle.

### 4. Tests

Pre-run gate denies within ~100ms when off; mid-run kill terminates the run (fake claude that sleeps; killed); toggle writes audit; unauth toggle → 401; confirm-on-destructive enforced.

**User Choice** (autonomous — selected by the implementing session; the epic-loop is in autonomous mode, no user prompt during Design):

- **Choice 1 — 1A**: new sibling route `/settings/autofix` with a horizontal sub-nav inside `SettingsLayout` (Logs | Auto-fix). Adds `SettingsAutofixPage.tsx`. Rationale: reserves the surface STAGE-009-010 will fill without route churn, keeps `SettingsLogsPage` semantically clean, discoverable under Settings.
- **Choice 2 — 2C + Push + SIGKILL + new `DockerSocketClient.kill_container(container_id, signal="SIGKILL")`** (modeled on `stop_container`, hits `POST /containers/{id}/kill?signal={signal}` over UDS). Trigger: the toggle endpoint calls `orchestrator.kill_inflight(reason, killed_by)` which reads `_current_run` under an asyncio.Lock, calls `docker_client.kill_container(...)`, awaits the exec task's completion within a ~2s deadline, then persists partial state + writes the `autofix.killed` audit row on that same code path. Rationale: mirrors the proven e2e test `test_docker_kill_terminates_inflight_exec`; deterministic partial-state persistence makes 100% branch coverage feasible; single-click UX for a panic control; SIGKILL is the only signal defensible under non-negotiable #7 ("immediately").
- **Choice 3 — 3C**: migration `0048_runbook_runs_killed_at.py` adds a single `killed_at TEXT NULL` column on `runbook_runs`. The kill reason + actor live in `audit_log` (`what="autofix.killed"`, `after_json` includes `runbook_run_id`, `reason`, `killed_by`). Tests assert both surfaces. Rationale: audit_log is already the non-negotiable-#4 compliance surface; duplicating reason+actor in the row would create two sources of truth. `killed_at IS NOT NULL` is the trivial "was this partial?" query for 010's history screen later.
- **Choice 4 — A-LOOSE + B-BOTH**. Backend uses `.strip().lower()` equality (matches `ConfirmPhraseDialog`'s case-insensitive behavior — eliminates a whole FE/BE mismatch bug class). Confirm phrases are context-aware: `"disable auto-fix"` when transitioning `on → off`, `"enable auto-fix"` when transitioning `off → on`. Both transitions require the phrase — re-arming a subsystem that runs `claude --dangerously-skip-permissions` is as safety-relevant as disabling it. Wrong/missing phrase → HTTP 400.
