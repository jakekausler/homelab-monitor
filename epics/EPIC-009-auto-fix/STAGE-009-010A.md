# STAGE-009-010A: Auto-fix UI — manual "Run fix" trigger (backend endpoint + UI button + risky-PATCH defense-in-depth)

## Status: Not Started

## Overview

Build the operator-initiated manual-trigger surface deferred from STAGE-009-010. Adds a backend endpoint (`POST /api/runbooks/{id}/trigger` or equivalent) that lets an authenticated operator kick off a runbook against a synthetic operator-initiated alert (no real alert required), honoring ALL seven non-negotiables (allow-list, rate-limit, cooldown, kill-switch, risky→dry-run+approval, audit, identity). Adds a per-card "Run fix" button + Dialog modal to STAGE-009-010's Runbooks catalog cards (dry-vs-real toggle FORCED to dry for risky, confirm-on-destructive for real via ConfirmPhraseDialog). Also adds a defense-in-depth backend rejection of `PATCH /api/runbooks/{id}` when the request tries to set `auto_trigger=true` on a `risky` runbook (today the safety net is exec-time only via `dry_run_required` — the PATCH itself is permitted).

**Vertical slice:** after this stage, a user browsing `/runbooks` can click "Run fix" on any card, choose dry/real (locked to Dry for risky), confirm-on-destructive if real, and see the resulting run appear in the pending-approvals panel (for risky/dry) or as a real-run outcome (for safe/real). Desktop + Mobile viewport sign-off.

**Origin:** deferred from STAGE-009-010 Design 2026-07-02.

**Spec references:** §9.2 (Runbooks screen "Run now / Dry run"), §7.4 non-negotiable #1 (Trigger allow-list), §7.4 non-negotiable #5 (Dry-run + approval).

## Cross-cutting standards (from EPIC-009 cross-stage acceptance criteria)

- The trigger endpoint honors ALL seven non-negotiables. The code-reviewer (Opus) must verify per-non-negotiable PASS/FAIL with justification.
- Backend allow-list semantics for operator-initiated runs: an operator may trigger ANY enabled runbook (bypassing the alert-match allow-list is the point of manual-trigger). Kill-switch, rate-limit, cooldown, and dry-run gates still apply as normal.
- Audit trail: `runbook_runs.initiated_by='operator'` (new column OR new field on prompt/metadata) records the user identity. Verify migration schema.
- 401 on unauthenticated; 403 on CSRF missing; explicit denial responses for each gate.

## Concrete deliverables

### 1. Backend trigger endpoint

`POST /api/runbooks/{id}/trigger` (auth + CSRF). Request body: `{ mode: "dry" | "real" }` (mode required; server rejects real for risky runbooks with 400 `dry_run_required_for_risky` even if UI lockout is bypassed). Response: `{ run_id, outcome, denial_reason?, real_run_id?, approval_id? }`. Errors: 409 with codes `kill_switch`, `rate_limit`, `cooldown`, `already_running`, plus 400 `dry_run_required_for_risky`, 404 `runbook_not_found`, 409 `runbook_disabled`.

### 2. Backend defense-in-depth for risky PATCH

`PATCH /api/runbooks/{id}` rejects requests that would set `auto_trigger=true` while `risk_tag=='risky'` (returns 400 with code `risky_auto_trigger_denied`). Matches the frontend info-tooltip semantic from STAGE-009-010.

### 3. Frontend Run-fix button + modal

Per-catalog-card "Run fix" button (STAGE-009-010's card layout). Radix Dialog modal shows: runbook name, mode radio (Dry / Real; Real disabled for risky with inline explanation), confirm-on-destructive via ConfirmPhraseDialog if Real, submit button. On dry-run success: closes modal, invalidates pending-approvals query so the new approval appears in 010's panel. On real-run success: closes modal, shows toast with outcome + run_id.

### 4. Audit surface

`initiated_by='operator'` recorded on operator-triggered `runbook_runs` rows; audit_log rows include the user identity.

### 5. Tests + sign-off

Backend pytest: kill-switch denial, rate-limit denial, cooldown denial, already-running denial, risky→real rejection, risky→dry produces approval, safe→real runs, 401/403, PATCH risky auto_trigger rejection. Vitest: modal opens from Run-fix button; risky card's Real radio is disabled; typed-phrase confirm required for real; error toasts render denial reasons. Desktop + Mobile viewport sign-off.
