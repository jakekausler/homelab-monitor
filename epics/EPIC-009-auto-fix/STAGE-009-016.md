# STAGE-009-016: Whole-folder + markdown drift hash

## Status: Not Started

## Overview

Extend `runbooks.content_hash` (currently YAML-only, per STAGE-009-001) to hash the entire runbook folder including `*.md` files and any sibling files. This closes the drift-detection gap owed by STAGE-009-001 and STAGE-009-006: currently a user editing `README.md` or auxiliary scripts under a runbook folder does NOT invalidate a pinned dry-run approval, which weakens non-negotiable #4 (content_hash must reflect the authoritative content used by the run).

**Deferred from:** STAGE-009-012 Design (2026-07-03). Origin regression items filed under STAGE-009-001 and STAGE-009-006.

## Concrete deliverables

1. Extend `compute_runbook_content_hash` (currently config-hash only) to include all files under the runbook folder — deterministic ordering, canonicalize line endings, exclude transient/hidden files.
2. Migration or backfill pass: recompute `runbooks.content_hash` for all existing rows on migration OR on next `POST /api/runbooks/refresh` scan.
3. Deploy behavior doc: existing `runbook_run_approvals.pinned_runbook_hash` rows become stale after this stage lands — every pending approval will be auto-rejected on the next `POST /autofix/approvals/{id}/approve` as RUNBOOK_CHANGED. Document + test this expected behavior (do NOT silently invalidate — the 409 response is the audit trail).
4. Tests: mutate `README.md` under a runbook folder + POST approve → 409 `runbook_changed_since_plan`; add + remove a sibling `.txt` → hash changes; deterministic hash across two identical folder copies.
