# STAGE-009-014: Docker intent gateway — schema, validator, executor

## Status: Not Started

## Overview

Enforce the docker dimension of non-negotiable #2 at execution time. STAGE-009-008 landed the policy layer (declared capability envelope, validated + audited at grant time, no docker access granted to the fixer). STAGE-009-014 lands the mechanism: the fixer emits a structured intent file (`docker-intent.json` in its transcript dir); the orchestrator parses the intent post-exec, validates each intent against the runbook's `DockerCapability` envelope captured by 008's `autofix.grant_resolved` audit, and executes valid intents via the existing `DockerClient` (owned by EPIC-003). Invalid intents are audited and dropped. This is a POLICY-LAYER stage complement — the fixer never holds a docker socket; the enforcement point is the monitor's already-hardened `DockerClient` seam.

**Vertical slice:** after this stage, a runbook declaring `docker: {container: pihole-unbound, allowed_actions: [restart]}` can produce a full end-to-end action: fixer analyzes → writes `{"container":"pihole-unbound","action":"restart"}` intent → orchestrator validates against 008's envelope → orchestrator invokes `DockerClient.restart_container("pihole-unbound")` → audits `autofix.intent_executed`. An intent naming an undeclared container OR an action outside `allowed_actions` is REJECTED (`autofix.intent_denied` audit) without touching docker. This unblocks STAGE-009-013 (pihole-restart-loop E2E).

**Spec references:** §7.4 (non-negotiable #2 docker dimension: fixer grants scoped to declared container+actions). EPIC-009 LOCKED Decision 2 (docker primary; per-runbook scoped capabilities). Consumes STAGE-009-008's `_ResolvedGrants` and `autofix.grant_resolved` audit contract.

## Concrete deliverables

### 1. Intent schema

New Pydantic model `DockerIntent` (in a new module `apps/monitor/homelab_monitor/kernel/autofix/intents.py`): `container: str`, `action: Literal["restart"]` (MVP action set; extensible). Structured file: `<transcript_dir>/<run_id>/docker-intent.json` — a JSON list of `DockerIntent` objects (multiple intents per run allowed but typically one). Parser tolerates missing file (no-op — most runs won't have intents).

### 2. Validator

`_validate_intent(intent: DockerIntent, envelope: DockerCapability | None) -> Literal["accept"] | tuple["deny", str]`. Rejects: missing envelope (`docker` not declared) → `("deny", "docker not in scoped_capabilities")`; container mismatch → `("deny", "container '<x>' not in envelope")`; action not in `allowed_actions` → `("deny", "action '<x>' not in allowed_actions")`. Every reject branch is coverable by a unit test.

### 3. Executor

Uses existing `homelab_monitor.kernel.docker.DockerClient` (EPIC-003). Calls `docker_client.restart_container(name)` for `action=="restart"`. Wrap in try/except → surface docker errors as `autofix.intent_execution_error` audit; the run's `exit_code` is inherited from Claude's exec — an intent execution error does NOT change the run outcome (audit tracks it separately).

### 4. Orchestrator wiring

Post-`_exec_claude`, before `_persist_outcome`: parse intents from `<transcript_dir>/<run_id>/docker-intent.json`, iterate, validate each against the run's grant envelope (loaded fresh from `_ResolvedGrants` via `_resolve_grants` — same helper 008 introduced), execute or deny with audit. Zero intents = no-op (most runs). Multiple intents = per-intent audit + execution.

### 5. Tests

- Zero intents (no file) → no-op, no audit, run persists normally.
- One valid intent → executed, `autofix.intent_executed` audit, run persists normally.
- Container mismatch → `autofix.intent_denied` audit, no docker call.
- Action not in `allowed_actions` → `autofix.intent_denied` audit, no docker call.
- Multiple intents (2 valid, 1 invalid) → 2 executed, 1 denied, 3 audit rows.
- Docker call raises → `autofix.intent_execution_error` audit, run outcome unchanged.
- Malformed intent JSON → `autofix.intent_denied` with `reason="malformed_intent_file"`; run persists normally.
- No `DockerCapability` in envelope but intent file present → all intents denied.
