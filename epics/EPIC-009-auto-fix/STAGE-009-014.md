# STAGE-009-014: Docker intent gateway — schema, validator, executor

## Status: Complete

## Overview

Enforce the docker dimension of non-negotiable #2 at execution time. STAGE-009-008 landed the policy layer (declared capability envelope, validated + audited at grant time, no docker access granted to the fixer). STAGE-009-014 lands the mechanism: the fixer emits a structured intent file (`docker-intent.json` in its transcript dir); the orchestrator parses the intent post-exec, validates each intent against the runbook's `DockerCapability` envelope captured by 008's `autofix.grant_resolved` audit, and executes valid intents via the existing `DockerClient` (owned by EPIC-003). Invalid intents are audited and dropped. This is a POLICY-LAYER stage complement — the fixer never holds a docker socket; the enforcement point is the monitor's already-hardened `DockerClient` seam.

**Vertical slice:** after this stage, a runbook declaring `docker: {container: pihole-unbound, allowed_actions: [restart]}` can produce a full end-to-end action: fixer analyzes → writes `{"container":"pihole-unbound","action":"restart"}` intent → orchestrator validates against 008's envelope → orchestrator invokes `DockerClient.restart_container("pihole-unbound")` → audits `autofix.intent_executed`. An intent naming an undeclared container OR an action outside `allowed_actions` is REJECTED (`autofix.intent_denied` audit) without touching docker. This unblocks STAGE-009-013 (pihole-restart-loop E2E).

**Spec references:** §7.4 (non-negotiable #2 docker dimension: fixer grants scoped to declared container+actions). EPIC-009 LOCKED Decision 2 (docker primary; per-runbook scoped capabilities). Consumes STAGE-009-008's `_ResolvedGrants` and `autofix.grant_resolved` audit contract.

## Concrete deliverables

### 1. Intent schema

New Pydantic model `DockerIntent` (in a new module `apps/monitor/homelab_monitor/kernel/autofix/intents.py`): `container: str`, `action: Literal["restart"]` (MVP action set; extensible). Structured file: `<transcript_dir>/<run_id>/docker-intent.json` — a JSON list of `DockerIntent` objects (multiple intents per run allowed but typically one). Parser tolerates missing file (no-op — most runs won't have intents).

### 2. Validator

`_validate_intent(intent: DockerIntent, envelope: DockerCapability | None) -> Literal["accept"] | tuple["deny", str]`. Rejects: missing envelope (`docker` not declared) → `("deny", "docker not in scoped_capabilities")`; container mismatch → `("deny", "container '<x>' not in envelope")`; action not in `allowed_actions` → `("deny", "action '<x>' not in allowed_actions")`. Every reject branch is coverable by a unit test.

### 3. Executor

Uses existing `homelab_monitor.kernel.docker.DockerClient` (EPIC-003). Calls `docker_client.restart_container(name)` for `action=="restart"`. Wrap in try/except → surface docker errors as `autofix.intent_execution_error` audit; the run's `exit_code` is inherited from Claude's exec — an intent execution error does NOT change the run outcome (audit tracks it separately).

### 4. Orchestrator wiring

Post-`_exec_claude`, before `_persist_outcome`: parse intents from `<transcript_dir>/<run_id>/docker-intent.json`, iterate, validate each against the run's grant envelope (loaded fresh from `_ResolvedGrants` via `_resolve_grants` — same helper 008 introduced), execute or deny with audit. Zero intents = no-op (most runs). Multiple intents = per-intent audit + execution.

### 5. Tests

- Zero intents (no file) → no-op, no audit, run persists normally.
- One valid intent → executed, `autofix.intent_executed` audit, run persists normally.
- Container mismatch → `autofix.intent_denied` audit, no docker call.
- Action not in `allowed_actions` → `autofix.intent_denied` audit, no docker call.
- Multiple intents (2 valid, 1 invalid) → 2 executed, 1 denied, 3 audit rows.
- Docker call raises → `autofix.intent_execution_error` audit, run outcome unchanged.
- Malformed intent JSON → `autofix.intent_denied` with `reason="malformed_intent_file"`; run persists normally.
- No `DockerCapability` in envelope but intent file present → all intents denied.

**Design decisions (D1..D8):**

| # | Decision | Selected | Rationale |
|---|----------|----------|-----------|
| D1 | Intent file location | A — `<transcript_dir>/<run_id>/docker-intent.json` | Reuses existing `:ro` audit-integrity mount (STAGE-009-003). Deterministic path (no PID-based scan). Rotation-coherent with STAGE-009-012. |
| D2 | Gateway placement in orchestrator | B — return `grants` from `_exec_claude`; execute intents in `_claim_and_exec` between exec and `_persist_outcome`. | D3 | Multi-intent validation ordering | A — validate all first; deny invalid per-intent; execute valid ones | Intents are independent by contract (each intent references its own container). A malformed intent is a signal (audited) but should not block valid siblings. |
| D4 | Multi-intent partial failure semantics | C — halt on `DockerSocketConnectionError` (daemon down = systemic); continue on `DockerSocketProtocolError` (per-container issue) | The exception hierarchy already carries the signal. Daemon-down noise floor is real; per-container failures genuinely independent. Skipped intents audited as `autofix.intent_skipped_after_error`. |
| D5 | Audit event names | A — `autofix.intent_executed` / `autofix.intent_denied` / `autofix.intent_exec_error` / `autofix.intent_malformed` (+ `autofix.intent_skipped_after_error` for D4-C, `autofix.intent_kill_switched` for D6-C, `autofix.intent_dry_planned` for D7-B, `autofix.intent_gateway_failed` for I3 exception handling) | Matches existing `autofix.<past-tense-verb>` + shortened `exec_error` convention (not `execution_error`). Distinct `what` values → clean `COUNT(*) GROUP BY what` dashboarding for STAGE-009-011. |
| D6 | Kill-switch re-check semantics | C — re-read `autofix_enabled` once at intent-gateway start (batch decision). Matches typical 1-2 intents per run. Upgrade to per-intent recheck is a 5-min change if batch sizes grow. |
| D7 | Dry-run behavior | B — parse + validate intents in dry-run; audit each as `autofix.intent_dry_planned`; NEVER execute. Persistence to `alert_outcomes.dry_run_plan` deferred to STAGE-009-013. | Non-negotiable #5 preserved (dry-run produces plan, no execution). **Concrete architecture summary:**

- New module `apps/monitor/homelab_monitor/kernel/autofix/intents.py` — `DockerIntent(BaseModel, extra="forbid")` with `container: str`, `action: Literal["restart"]` (MVP); `parse_intents(intent_path: Path) -> list[DockerIntent]` (tolerates missing file, returns empty list; malformed file raises `MalformedIntentFileError`); `validate_intent(intent: DockerIntent, grants: ResolvedGrants) -> IntentValidation` (accept or deny + reason string).
- New dataclass `ExecOutcome` in `apps/monitor/homelab_monitor/kernel/autofix/types.py` — bundles `exec_result`, `transcript_path`, `error_msg`, `errored`, `feedback_items`, `grants`. Replaces the 5-tuple return from `_exec_claude`.
- Orchestrator changes in `apps/monitor/homelab_monitor/kernel/autofix/orchestrator.py`:
  - `_exec_claude` returns `ExecOutcome` (grants included).
  - New method `_execute_intents(*, run_id, alert, record, grants, transcript_dir, dry: bool) -> None` — reads `<transcript_dir>/<run_id>/docker-intent.json`, iterates. Per-intent audit rows written independently via `insert_audit` (NOT in `_persist_outcome`'s transaction — docker execs are non-transactional).
  - Wiring: `_claim_and_exec` calls `_execute_intents(dry=False)` after `_exec_claude` returns and BEFORE `_persist_outcome`. `_claim_and_store_dry` calls `_execute_intents(dry=True)` after `_exec_claude(dry=True)` returns.
  - Kill-switch re-check (D6-C): first call inside `_execute_intents` reads `self._app_settings_repo.get("autofix_enabled")`; on false emit `autofix.intent_kill_switched` (with `run_id`, `intent_count`) and return.
- Uses existing `DockerSocketClient.restart_container(container_id, timeout_seconds=None)` on `self._docker`.
- Fake-claude extended with a new env var (`FAKE_CLAUDE_DOCKER_INTENT`) that, when set, writes a `docker-intent.json` under the run's transcript dir. Tests inject via `FAKE_CLAUDE_DOCKER_INTENT`.

### Design Notes

**Key implementation details to carry forward to Build:**

1. **Docker client is `DockerSocketClient`, not `DockerClient`.** Located at `apps/monitor/homelab_monitor/kernel/docker/socket_client.py`. Method signature: `async def restart_container(container_id: str, *, timeout_seconds: int | None = None) -> None`. HTTP 304 (idempotent) treated as success.

2. **`_docker` is already a member of `AutoFixOrchestrator`.** No new dependency injection needed. Used for all docker operations in the module.

3. **`grants` return-value change (D2-B).** Currently `_exec_claude` returns a 5-tuple; the design promotes this to an `ExecOutcome` dataclass that includes `grants`. Both call sites (`_claim_and_exec` and `_claim_and_store_dry`) updated symmetrically.
