# STAGE-009-008: Per-runbook scoped-capability granting + fixer-runner egress control

## Status: Complete

## Overview

Make the scoped capabilities the orchestrator grants actually real at exec time (LOCKED Decision 2). A runbook's config file declares its capabilities; this stage implements how those become concrete grants on the `fixer-runner` at the moment of a `docker exec`: docker-socket access (for local container-action runbooks like the pihole example), optional bind-mounts, an egress allow-list, and — for READ access — citing an existing EPIC-017 SSH `target_id`. Also enforces the network posture: inbound to the fixer is denied; outbound is allow-listed (the Anthropic API is always allowed; any other endpoint only if the runbook declares it).

**Vertical slice:** after this stage, a runbook declaring `docker: {container: pihole-unbound, actions: [restart]}` causes the fixer to be granted exactly that docker capability and nothing broader; a runbook declaring no docker capability cannot reach the socket; egress beyond the allow-list is denied. Per non-negotiable #2, capabilities are exactly what's declared — never broad.

**Spec references:** §7.4 (network model: egress allowed for Anthropic API, inbound denied; #2 never broad paths), §7.5 (network model — private docker net), §10.2 (volume mounts). EPIC-009 LOCKED Decision 2 (per-runbook scoped capabilities; docker primary; SSH target_id read-only; verified EPIC-007/008 observe-only + EPIC-017 forced-command read-only).

## Concrete deliverables

### 1. Capability granting at exec time

Translate a runbook's declared `scoped_capabilities` into concrete grants on the `fixer-runner` for that exec: docker-socket exposure (scoped to the declared container + actions where feasible), bind-mounts, the egress allow-list. A capability not declared is not granted.

### 2. Egress control

Inbound denied; outbound allow-listed (Anthropic API always; runbook-declared endpoints only). Document how this composes with the private docker network (§7.5).

### 3. SSH target_id read reference

A runbook may cite an existing EPIC-017 SSH `target_id` for READ access (the forced-command is server-pinned, read-only). Wire the reference; do NOT create new write-capable targets.

### 4. Tests

Declared docker capability → granted; undeclared docker → denied (cannot reach socket); egress beyond allow-list → denied; Anthropic egress → allowed; SSH target_id read-ref resolves to an existing EPIC-017 target.

## Design Phase

**Status**: [x] Design (Complete)

**Approach Selected** (autonomous loop — chosen by implementing session):

Composite: **1B + 2E-lite + 3E + 4D**. Separates policy (what is allowed) from mechanism (how it is enforced). STAGE-009-008 owns policy only; two new stages (014, 015) own mechanism.

- **Config propagation (1B) — File-authoritative runtime re-read.** Orchestrator loads `RunbookConfig` at exec-start via existing `RunbookConfig.load_from_path` on `Path(record.path)`; extracts `scoped_capabilities` freshly per exec. Single source of truth — no DB blob, no in-memory cache drift. Aligns with the LOCKED Decision 2 file-authoritative registry and existing content_hash drift detection. Fail-closed on missing/malformed YAML at exec time (`errored=True`, `error_msg="scoped_capabilities unavailable"`, audited as `autofix.grant_failed`).

- **Docker capability (2E-lite) — Policy-layer only, execution mechanism deferred to STAGE-009-014.** STAGE-009-008 does NOT grant the fixer container a docker socket, proxy, or CLI wrapper. Instead, it validates + audits the declared `DockerCapability` envelope. The fixer has zero docker access this stage. The actual intent-emission + validator + executor lands in STAGE-009-014 (Docker intent gateway). This substitutes the card's "docker-socket exposure … scoped to the declared container" premise ("where feasible" hedge) with a safer post-run intent pattern. Non-negotiables #2 + #3 fully preserved: fixer cannot even attempt an undeclared action because it holds no docker access at all.

- **Egress (3E) — Declaration + warning-audit today, enforcement in STAGE-009-015.** 008 validates the `egress: list[str]` value shape; audits it as `granted_egress` under `autofix.exec_started`; emits a per-real-exec warning `autofix.egress_unenforced` so the gap is impossible to forget. Enforcement (HTTPS proxy sidecar on `fixer-egress` + iptables/nftables DROP for non-proxy outbound) is owned by STAGE-009-015. Honest downgrade: non-negotiable #2's egress dimension is DECLARED but not ENFORCED until 015 lands.

- **SSH target_id (4D) — Reference-only, fail-closed.** 008 validates `SshCapability.target_id` resolves against `load_ssh_target_configs()` (imported from `homelab_monitor.kernel.ssh.config`); on miss, fail closed (`autofix.grant_failed` audit, `errored=True`, `error_msg="unknown ssh target_id: <id>"`); on hit, audit as `granted_ssh_target_id`. No SSH secret material moves into the fixer container. Server-side forced-command already enforces read-only at the target. Actual SSH execution from a runbook is out of scope per the card ("Wire the reference; do NOT create new write-capable targets") and can be a future stage if it becomes needed.

**Autonomous-selection rationale:** The card's Deliverable 1 phrasing ("docker-socket exposure … scoped to the declared container + actions **where feasible**") already hedges the mechanism. The safest realization of that hedge is to NOT expose the socket at all. This creates a clean policy/mechanism split (008/014) that also produces smaller, individually-reviewable stages — each with 100% branch coverage tractable. The composite decision honors non-negotiables #2 (fixer sees only declared capabilities), #3 (fixer identity `homelab-fixer` not elevated), #4 (every grant translation audited) unconditionally. Non-negotiable #2's egress dimension is honestly deferred to STAGE-009-015 (named, tracked, non-silent).

**Design Notes**:

**Insertion point in orchestrator.** Grant translation slots into `_exec_claude` (apps/monitor/homelab_monitor/kernel/autofix/orchestrator.py:272-334) between L286 (post-env-computation) and L297 (pre-kill-switch-publish). STAGE-009-007's `_current_run` publish/clear pattern (L297-303 / L323-329) and `_kill_lock` semantics MUST remain intact — grants happen BEFORE the kill-target is published so a failed grant never leaves a phantom kill target.

**Config propagation seam.** New helper `_resolve_grants(record: RunbookRecord) -> _ResolvedGrants` on `AutoFixOrchestrator`. Loads the runbook YAML via existing loader (`RunbookConfig.load_from_path(Path(record.path))`). Returns a small frozen dataclass (`_ResolvedGrants(docker: DockerCapability | None, ssh: SshCapability | None, egress: tuple[str, ...])`). Called inside `_exec_claude` before the exec critical section. On failure (file missing, YAML invalid, unknown ssh target_id): raise a new `GrantResolutionError` — caught by `_exec_claude`, converted to a synthesized `ExecResult(exit_code=1)` with `errored=True`, `error_msg` set, `autofix.grant_failed` audit written, and the run persists as `errored`.

**Audit vocabulary (additions).** New audit `what` values:
- `autofix.grant_resolved` — emitted at successful grant translation (before exec). `after={runbook_id, alert_id, run_id, granted_docker: DockerCapability|None, granted_ssh_target_id: str|None, granted_egress: [str, ...]}`.
- `autofix.grant_failed` — emitted at grant failure. `after={runbook_id, alert_id, run_id, reason: str, detail: str}`.
- `autofix.egress_unenforced` — WARNING-level; emitted at every real (non-dry) exec that declares egress endpoints. `after={runbook_id, alert_id, run_id, declared_egress: [str, ...], owner_stage: "STAGE-009-015"}`.

**Types.** `_ResolvedGrants` is internal (frozen dataclass in `autofix/types.py`); `GrantResolutionError` is a new exception in `autofix/types.py` (or a dedicated `autofix/grants.py` module — choose during Build to keep the file split coherent). No new Pydantic model needed — `DockerCapability`, `SshCapability`, `ScopedCapabilities` already exist in `kernel/runbooks/config.py`.

**Non-negotiables — grant-audited posture.** #2: declared capability envelope is the sole authority (validated against real code by grant translator; audited); fixer has NO docker access → cannot exceed the envelope even by trying. #3: fixer identity `homelab-fixer` (UID 1002) preserved; no root elevation, no docker.sock mount added in 008. #4: every grant translation writes `autofix.grant_resolved` (success) or `autofix.grant_failed` (fail); every real exec with declared egress writes `autofix.egress_unenforced` warning. #7: kill switch preserved untouched (grants happen before `_current_run` publish; if grant fails, no kill target registered).

**What NOT to touch this stage.**
1. `_current_run` publish/clear frame (L297-303 / L323-329).
2. `_kill_lock` critical sections.
3. The `_check_operational_gates` order (kill_switch → allow_list → rate_limit → cooldown → risky_blocked → already_running).
4. `FixerRunnerConfig` fields (`container`, `fixer_user`, etc.) — no new fields this stage; grants operate on runbook-config data alone.
5. Compose file `fixer-runner` service — NO new mounts, NO cap_add, NO network changes in 008. Egress enforcement infra is 015's job. Docker socket exposure is 014's job. This stage is BACKEND-only in touched code.
6. Migration files — no schema change.

**Test surface plan.**
- Grant-translation happy path: valid `scoped_capabilities` with docker + ssh + egress → `_ResolvedGrants` populated, `autofix.grant_resolved` audit written, exec proceeds.
- Grant-translation missing file: YAML file removed after registry refresh but before exec → `GrantResolutionError` → `autofix.grant_failed` audit → `errored` run persisted.
- Grant-translation malformed YAML: file exists but Pydantic validation fails → same path.
- SSH ref unknown: `target_id` not in `load_ssh_target_configs()` → `GrantResolutionError` → `autofix.grant_failed` → `errored`.
- Egress declared: real exec with `egress=["api.anthropic.com"]` → `autofix.egress_unenforced` warning audit emitted, exec proceeds.
- Egress empty: real exec with `egress=[]` → NO warning audit (nothing to enforce).
- Dry run: `autofix.grant_resolved` written (still audit the envelope) but `autofix.egress_unenforced` NOT emitted (dry runs don't touch network).
- Grant happens before `_current_run` publish: kill-switch integration test — grant failure produces zero kill-target registration.

**Deployment surface.** BACKEND-only stage. No compose changes. No Dockerfile changes. No frontend surface. Refinement's host-integration validation is: deploy 008 impl to instance A (rebuild+redeploy prod stack per standing auth), fire a synthetic alert against a test runbook with docker+ssh+egress declarations, observe `autofix.grant_resolved` in `audit_log`; then fire against a runbook with an unknown ssh target_id and observe `autofix.grant_failed` + `errored=True` run row.

**Coverage.** 100% branch coverage required by the epic-wide gate. All new branches (grant success, file missing, YAML invalid, ssh unknown, egress declared, egress empty, dry vs real) are reachable via existing test scaffolding (`tests/kernel/autofix/`). No `@pytest.mark.slow`; no rig-dependent scenarios.

**Deferrals (tracked)** — per no-silent-deferral rule, every deferred deliverable lands on a named stage:

- **Docker capability execution mechanism** → **STAGE-009-014** (NEW): "Docker intent gateway — schema, validator, executor". Scope: fixer emits `docker-intent.json` in transcript dir → orchestrator parses post-exec → validates each intent against the runbook's `DockerCapability` envelope (008's grant record) → executes valid intents via existing `DockerClient` → audits `autofix.intent_executed` / `autofix.intent_denied`. This is where non-negotiable #2's docker dimension gets ENFORCED at execution time.
- **Fixer-runner egress enforcement** → **STAGE-009-015** (NEW): "fixer-runner egress enforcement (HTTPS proxy + host firewall)". Scope: add HTTPS-proxy sidecar on the `fixer-egress` docker network; configure iptables/nftables on the docker host to DROP outbound from `fixer-runner` container's netns except via the proxy; proxy enforces the `granted_egress` allow-list captured in 008's audit. Anthropic API always allowed (proxy config). This is where non-negotiable #2's egress dimension gets ENFORCED.
- **Runbook-initiated SSH read execution** → NOT stage-tracked this epic. Reason: EPIC-017 SSH targets are server-side-forced-command read-only observation targets (per `project_ssh_targets_and_framework.md`); no runbook currently needs to invoke SSH mid-analysis. If a future runbook DOES need this, it would follow the same intent-pattern as STAGE-009-014 (fixer writes `ssh-intent.json`, monitor executes via `AsyncSshClientFactory`). Not creating a placeholder stage without concrete demand.
- **Epic denominator update**: EPIC-009 stage count goes from 13 → **15**. STAGE-009-013 (epic-closing pihole example) will depend on STAGE-009-014 (its declared docker capability needs the intent gateway to actually work end-to-end). Stage-order-of-execution: 008 → 009 → 010 → 011 → 012 → 014 → 015 → 013. Sequential-dependency-ordering rule respected: 013 (dependent on 014) has higher number than 014.
