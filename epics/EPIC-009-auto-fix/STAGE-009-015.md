# STAGE-009-015: fixer-runner egress enforcement (HTTPS proxy + host firewall)

## Status: Not Started

## Overview

Enforce the egress dimension of non-negotiable #2 at network layer. STAGE-009-008 landed egress DECLARATION + a `autofix.egress_unenforced` warning audit on every real exec; enforcement is this stage's job. Add an HTTPS proxy sidecar on the `fixer-egress` docker network + host-side iptables/nftables rules that DROP outbound from the `fixer-runner` container's network namespace except through the proxy. The proxy enforces the runbook's declared `egress` allow-list (captured in 008's `autofix.grant_resolved` audit). The Anthropic API is always in the proxy's allow-list (baseline); runbook-declared endpoints are added per exec.

**Vertical slice:** after this stage, a real exec of a runbook declaring `egress: ["api.anthropic.com"]` can reach ONLY Anthropic; an attempt to reach an undeclared endpoint (curl, DNS, TCP connect) DROPS at the host firewall or is rejected by the proxy. The `autofix.egress_unenforced` warning audit stops firing (or transitions to `autofix.egress_enforced` informational).

**Spec references:** §7.4 (network posture: egress allowed for Anthropic; inbound denied), §7.5 (private docker network `homelab-monitor-net`; `fixer-egress` as separate network in EPIC-009). EPIC-009 LOCKED Decision 2 (egress allow-list per runbook).

## Concrete deliverables

### 1. HTTPS proxy sidecar

New compose service (profile `fixer`) — an egress proxy container (envoy or squid, decided in Design) on the `fixer-egress` network. Proxy config generated per-exec (or dynamic): baseline allow-list = Anthropic API + `install.claude.ai` (for auto-update, if enabled) + DNS. Runbook-declared endpoints added atop the baseline.

### 2. Host firewall rules

`scripts/host-setup.sh` gets a new section (or a new companion script) that installs iptables/nftables rules on the docker host: DROP all outbound from `fixer-runner`'s container netns except to the proxy's IP:port. Idempotent (`--check` verifies without mutation). Uninstall path (`--uninstall` or similar) that restores baseline.

### 3. Orchestrator: proxy config generation per exec

New helper `_configure_egress_for_exec(envelope: _ResolvedGrants) -> None` — writes proxy config (or updates dynamic-reload endpoint) with the union of baseline + `envelope.egress`. Called from `_exec_claude` after `_resolve_grants` succeeds, before `exec_capture`. Failure to configure = fail-closed (`autofix.egress_configuration_error` audit, run errored).

### 4. Audit: transition from `autofix.egress_unenforced` to `autofix.egress_enforced`

STAGE-009-008 emits `autofix.egress_unenforced`. This stage: STOP emitting `unenforced`; START emitting `autofix.egress_enforced` per real exec (informational, not warning). Migration note in changelog.

### 5. Tests

- Baseline exec (no runbook egress declared) → Anthropic reachable, non-Anthropic hosts unreachable (integration test using a disposable test container or the fake claude).
- Runbook-declared endpoint → reachable during exec, unreachable after exec completes (proxy config rolled back).
- Off-list endpoint → connection refused/dropped.
- Kill switch during exec → still kills fixer-runner despite proxy/firewall.
- Idempotent host-setup: `--check` twice is no-op; install twice is no-op.
