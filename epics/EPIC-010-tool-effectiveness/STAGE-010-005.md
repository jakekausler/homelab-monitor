# STAGE-010-005: EPIC-009 auto-fix outcome writer verification + `initiated_by` fix

## Status: Not Started

## Overview

Prod-DB recon 2026-07-05 showed `alert_outcomes` has zero rows for `outcome = 'auto_fixed'` despite the write path being present at `apps/monitor/homelab_monitor/kernel/autofix/orchestrator.py:2050-2052`. Two possible causes: (a) latent code bug preventing the write; (b) no successful auto-fix has landed on prod since the last data cleanup — STAGE-009-013 Refinement's real-mode auto-fix run happened AFTER the recon's snapshot. Diagnose.

Also picks up STAGE-009-013 regression item #3: operator-approved real runs get `initiated_by="alert"` in the `runbook_runs` row despite the operator having triggered the flow. Fix here (mechanical: `execute_approved` should thread `initiated_by="operator"` into `_claim_and_exec`).

**Retrofit for:** EPIC-009 (auto-fix outcome writer + operator attribution).

## Concrete deliverables

1. **Verify the auto-fix outcome writer.** Run the same E2E flow STAGE-009-013 used (scratch runbook + trigger + approve). Confirm `alert_outcomes` gets a row with `outcome = 'auto_fixed'`. If the write path IS firing but with a bug (wrong alert_id, wrong outcome value), fix. If it's not firing at all, diagnose why.
2. **Fix `initiated_by` mislabeling.** In `orchestrator.py`, `execute_approved` calls `_claim_and_exec` with the default `initiated_by="alert"`. Change to thread the actual initiator through: if the approval came from an operator-triggered dry-run, use `"operator"`; if the approval came from an alert-triggered dry-run, use `"alert"`. The dry-run row already has the correct `initiated_by`; use it as the source of truth for the approval.
3. Regression test coverage:
   - E2E test that operator-triggered dry-run → approve → real run produces a `runbook_runs` row with `initiated_by = 'operator'` (currently produces `'alert'` — this test would fail before the fix).
   - E2E test that alert-triggered dry-run → approve → real run produces a `runbook_runs` row with `initiated_by = 'alert'`.
   - Test that a successful auto-fix run writes exactly ONE `alert_outcomes` row with `outcome = 'auto_fixed'`, `decided_by = 'autofix'` (or however 009's code identifies it).
   - Test that a failed auto-fix run (exit_code != 0) does NOT write an outcome row.
4. Instance-A Refinement: reproduce STAGE-009-013's prod E2E flow, verify BOTH the `initiated_by` label AND the auto-fix outcome row appear correctly. Cleanup identical to 013's pattern.
