# STAGE-010-011: Recommendation engine

## Status: Not Started

## Overview

Turn scorecards into human-readable recommendations. Python predicates over `tool_scorecards` rows produce advisory suggestions like "SignatureWentSilent produced 158k alerts with 0.02% action_rate — recommend evaluate-if-rule-is-broken." Recommendations land in the `recommendations` table with `status='pending'`. UI inbox displays them with Apply / Dismiss / Snooze actions (Apply implementation is STAGE-010-012).

Starter rule set is small and hand-authored. Extensibility path: rules are Python callables registered in a module; adding a rule = writing a function + registering it. No YAML config; keep the rules in code because they need to inspect scorecard details in ways config can't easily express.

## Concrete deliverables

1. New module `kernel/analyzer/recommendations.py`:
   - Type: `RecommendationRule = Callable[[list[ScorecardRow]], list[Recommendation]]`.
   - Registry pattern: `@register_recommendation_rule`.
   - Starter rules:
     - **`recommend_disable_zero_unique`**: for each (dimension, dimension_value) where `unique_share == 0` AND `dedup_overlap > 0.95` in the 90d window: propose "Consider disabling {dimension_value} — it hasn't caught anything unique in 90 days and is duplicated 95%+ by other detectors."
     - **`recommend_evaluate_low_action_rate`**: for each (dimension, dimension_value) where `action_rate < 0.05` AND `alerts_emitted > 100` in the 30d window: propose "The action rate for {dimension_value} is under 5% over the last 30 days ({alerts_emitted} alerts, N acted). Consider tuning thresholds or disabling."
     - **`recommend_evaluate_zero_emissions`**: for each (dimension, dimension_value) where `alerts_emitted == 0` in the 90d window: propose "{dimension_value} hasn't fired in 90 days. Is the rule broken, or is the system healthy? Verify."
   - Each rule returns zero or more `Recommendation` DTOs which the engine deduplicates against existing `pending` rows (same `dimension_value` + `rule_name` → skip, so the same recommendation doesn't get created every night).
2. Nightly job `run_recommendation_engine()` runs after `scorecard_aggregator`.
3. Backend `GET /api/recommendations`:
   - Query params: `status` (default `pending`), `dimension` (optional), `limit`, `offset`.
   - Response: `{items: RecommendationOut[], total_count}`.
4. Frontend Recommendations Inbox component on the Tool Analysis page:
   - Card per pending recommendation.
   - Buttons: Apply (opens confirm-on-destructive dialog + Apply flow — implementation in 012), Dismiss (marks status=dismissed, decided_by=<user>), Snooze (marks status=snoozed for 30d, then rehydrates to pending — implement snooze rehydration in a follow-up if needed).
5. Test coverage:
   - Each starter rule produces expected recommendations against a fixture scorecard set.
   - Dedup logic: existing pending recommendation NOT re-created on second run.
   - Empty scorecards → zero recommendations, no crash.
   - Dismiss/Snooze mutations write correct row state + audit_log entry.
