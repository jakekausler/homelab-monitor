# STAGE-010-012: First "Apply" actions + epic-closing E2E validation

## Status: Not Started

## Overview

Epic-closing stage. Implement the "Apply" side of the recommendation flow with two operation types per EPIC-010 Decision 7:

- **`disable-vmalert-rule`** — rewrites the rule file to comment out the specific rule, calls vmalert's `/-/reload` endpoint, audit-logs the action. Used when the recommendation is "consider disabling {rule}."
- **`tag-as-known-noisy`** — writes a `rule_annotations` row (metadata-only, no behavior change beyond suppressing future recommendations against this rule). Used when the user wants to acknowledge "yes, this is noisy but I want to keep it for now."

Both routed through confirm-on-destructive (per spec §7.2) and audit_log.

The epic-closing E2E on prod exercises the full pipeline: Karma reconcile → backfill → nightly aggregation → generated recommendation → applied disable → verify rule is disabled + recommendation moves to `status='applied'`.

## Stage Flags

- Has Input Forms: [x] Yes — confirm-on-destructive dialogs for both Apply operations.
- Touches secrets / production data: [x] Yes — mutates rule files on the host filesystem AND triggers vmalert reload.

## Concrete deliverables

1. Backend `POST /api/recommendations/{id}/apply`:
   - Session auth + confirm-phrase (or session-PIN, matching the pattern from STAGE-009-010B / STAGE-009-013's approve endpoint).
   - Dispatches to the appropriate Apply operation based on `recommendation.rule_name`.
   - Wraps the operation in an audit-logged transaction.
   - Updates the recommendation row: `status='applied'`, `decided_at`, `decided_by`, `applied_action_id`.
2. Apply operation `disable_vmalert_rule(target_alertname)`:
   - Locates the rule in `deploy/vmalert/{metrics,logs}/*.yaml` (grep by `- alert: {alertname}`).
   - Comments out the rule block (preserves file structure, adds a `# DISABLED by recommendation {id} on {date}` marker above).
   - Calls `vmalert-metrics` and/or `vmalert-logs` `/-/reload` endpoints depending on which file was touched.
   - Verifies reload succeeded (health check on vmalert after reload).
   - Audit-logs the action with before-content (the original rule YAML) + after-content (the commented-out version).
3. Apply operation `tag_as_known_noisy(target_source_tool, target_alertgroup, target_alertname)`:
   - Writes a `rule_annotations` row.
   - Analyzer's recommendation engine (STAGE-010-011) checks this table before creating recommendations — suppresses future ones for tagged rules.
4. Backend `POST /api/recommendations/{id}/dismiss` and `POST /api/recommendations/{id}/snooze` — already partially in 011; ensure Apply-Dismiss-Snooze are all wired here.
5. Frontend:
   - Apply button on each recommendation card opens a confirm-on-destructive dialog showing the exact change to be made (for `disable-vmalert-rule`: show the rule YAML diff; for `tag-as-known-noisy`: show the annotation content).
   - After successful Apply, the recommendation card transitions to `status='applied'` with a link to the audit_log entry.
6. Test coverage:
   - Apply `disable-vmalert-rule` on a fixture rule file: file mutated correctly, vmalert reload called, audit row written.
   - Apply `tag-as-known-noisy`: annotation row written, subsequent recommendation-engine run does NOT re-recommend for that rule.
   - Confirm-phrase mismatch aborts.
   - vmalert reload failure: transaction rolls back (rule file restored), audit row records the failure.
7. **Epic-closing E2E on Instance A** — the vertical-slice validation:
   - Bring prod state to a clean baseline (kill switch off, prior EPIC-010 stages complete).
   - Trigger `hm analyzer run-now` to produce fresh scorecards + at least one recommendation.
   - Apply one recommendation via the UI (Desktop + Mobile viewport verification).
   - Verify the rule is disabled in the vmalert config file + vmalert reloaded + no new alerts of that rule fire in the next hour.
   - Verify the recommendation row transitioned to `status='applied'` with correct decided_by / decided_at / audit_log linkage.
   - Cleanup: manually re-enable the rule that was disabled (uncomment + reload) OR leave disabled if the recommendation was correct.
