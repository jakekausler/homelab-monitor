# STAGE-010-008: Tool Analysis UI (read-only, multi-dimensional)

## Status: Not Started

## Overview

The first user-visible slice of EPIC-010. New `/tool-analysis` route in the SPA. Default view: per-`alertgroup` cards (39 groups is the right cardinality for a screen). Each card shows for the selected window: alerts-emitted sparkline, action_rate bar, unique-share percentage, dedup_overlap percentage. Dimension picker in the header switches the card set between `source_tool` / `category` / `target_kind` / `alertgroup` / `alertname`. Window picker: 7d / 30d / 90d. Clicking a card drills down to a per-alertname breakdown of that group (for source_tool / category / target_kind / alertgroup drill-downs) or the raw alerts list (for alertname drill-down).

## Concrete deliverables

1. Backend `GET /api/tool-scorecards`:
   - Query params: `dimension` (required — one of the 5), `window` (default `30d`), `limit` (default 100), `offset` (default 0).
   - Response: `{items: ScorecardOut[], total_count, dimension, window}` where each `ScorecardOut` mirrors the `tool_scorecards` row columns.
   - Session auth via `require_session()`.
   - New router `apps/monitor/homelab_monitor/kernel/api/routers/tool_scorecards.py`.
2. Frontend `apps/ui/src/routes/tool-analysis/`:
   - `ToolAnalysisPage.tsx` — page shell with dimension + window pickers, cards grid.
   - `ScorecardCard.tsx` — one card component. Sparkline via Recharts (already in deps). Percentage bars via existing Tailwind primitives.
   - `ScorecardsDrilldownPage.tsx` — drill-down route at `/tool-analysis/:dimension/:dimensionValue` showing per-`alertname` breakdown OR the raw alerts list.
   - `api/tool-scorecards.ts` — TanStack Query hooks: `useScorecardsList(dimension, window, page)`, `useScorecardDrilldown(dimension, dimensionValue, window)`.
   - Router integration: add `toolAnalysisLayoutRoute`, `toolAnalysisIndexRoute`, `toolAnalysisDrilldownRoute` to `apps/ui/src/router.tsx`.
   - Empty state: if `total_count == 0` (bootstrapping — no scorecard rows yet), render "The nightly aggregator hasn't run yet. Try again after 03:00 tomorrow, or trigger a manual run from the CLI." with the CLI command in a copy-paste-friendly `<code>` block.
3. Manual-run CLI: `hm analyzer run-now` triggers the aggregation job immediately (useful for stage validation + emergency recomputes).
4. Test coverage:
   - Backend: paginated list + filter by dimension + window returns expected rows on a fixture DB.
   - Backend: unauthenticated request returns 401.
   - Frontend: unit tests for `ScorecardCard` rendering (sparkline, bars, percentages) with various data shapes.
   - Frontend: TanStack Query hooks correctly memoize; filter changes trigger refetch.
   - Frontend: dimension picker actually swaps card set (integration test).
   - Empty-state renders when API returns `total_count: 0`.
5. Regression check: verify no regression on the existing `/autofix/history` route (they share the SPA shell + auth layout).
