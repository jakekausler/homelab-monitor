# STAGE-010-001: SignatureWentSilent purge + rule removal

## Status: Not Started

## Overview

Purge all `SignatureWentSilent` alerts from the `alerts` table (~158,782 rows on prod, ~94.5% of the population per 2026-07-05 recon) AND remove the vmalert rule that produces them. This is the epic's first stage because the noise dominates every dimension of the analyzer that comes later — filtering-at-analyzer hides the noise instead of fixing it. Explicit user sign-off recorded 2026-07-05 (planning session): "hard delete" chosen over archive/soft-delete options.

The underlying `homelab_log_signature_*` metric collection (from EPIC-004) is NOT touched; only the noisy alerting rule is deleted. If a future stage wants to re-enable signature-silent alerting with different thresholds, the metrics are still available.

**Retrofit for:** EPIC-004 (log pipeline / signature system).

## Stage Flags

## Concrete deliverables

1. Delete or comment-out the `SignatureWentSilent` rule from `deploy/vmalert/metrics/signature_silent.yaml` (or delete the entire file if it contains only this rule — verify during Design). Trigger vmalert `/-/reload` so the change takes effect without a container restart.
2. Emit an `audit_log` row BEFORE the delete, capturing the row count and reason. `who = "cli:stage-010-001-purge"` or the invoking session's principal. `what = "alerts_bulk_purged"`. `before = {alertname, row_count, source_tool, alertgroup}`. `after = null`.
3. `hm alerts purge --alertname=SignatureWentSilent --dry-run` CLI subcommand FIRST (shows count without deleting). Then `hm alerts purge --alertname=SignatureWentSilent --confirm-phrase="delete signature-silent noise"` executes the hard delete inside a single transaction (audit-log row + `DELETE FROM alerts WHERE alertname = 'SignatureWentSilent'`).
4. Regression test coverage:
   - `hm alerts purge` refuses without both `--alertname` and `--confirm-phrase` matching.
   - Confirm-phrase mismatch aborts with clear error.
   - Dry-run reports count without deleting.
   - Successful purge writes exactly ONE audit row + deletes exactly N alerts + does NOT touch other alertnames.
   - Idempotent second run: zero rows deleted, no audit row (or an audit row noting zero-count).
5. On prod (Refinement): verify existing SignatureWentSilent count (`SELECT COUNT(*) FROM alerts WHERE alertname='SignatureWentSilent'`), run the CLI with dry-run first, then execute the purge under supervision.
